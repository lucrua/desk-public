# Desk — UI polish pass: share readability, doc search, space-page tabs + file explorer, catalog clarity (design)

> **Status: DRAFT — pending owner review (2026-07-07).** Five owner-reported UX issues, each grounded in a read-only survey of `main@b0e7bf9` (post convergence-fix-pass). Presentational/UX only — **no access-boundary changes** (search reuses the existing viewer-scoped `searchDocs`; the catalog stays read-only). Verified in a real browser before "done" (per `verification-before-frontend-completion`).
> **Styling note:** this codebase uses **inline `style={{}}` with CSS custom properties** (`var(--ink)`, `var(--muted)`, `var(--hairline)`, `var(--surface)`, `var(--accent)`, `var(--font-serif|sans|mono)`) — no Tailwind, no CSS modules. Match that. Doc-body typography lives in `src/app/globals.css` (`.md-partner` / `.md-operator`).

## Findings (what's actually true on `main`)

- **Share reader** renders markdown at `19px` Newsreader serif / `line-height 1.72` / **~632px** measure (a `maxWidth:680` article box minus 24px×2 padding, border-box). Values are a deliberate "editorial" handoff but read as too big/narrow. The `680`(md)/`1100`(html) width literals are duplicated across ~5 spots in two page files. HTML shares render in a sandboxed iframe with their own CSS — **unaffected**.
- **Doc search backend is 100% built and tested** — `searchDocs()` (`src/lib/docs.ts:831`) does one weighted FTS query (title weight A, content weight B) over `docs.search_tsv`, viewer-scoped identically to `listDocs`, returning `rank` + a safe delimiter-encoded `snippet`. Exposed via `GET /api/docs?q=` and MCP `search_docs` (both `isStaff`-gated). **There is no search UI.** Pre-built but unused snippet helpers exist: `splitSnippet`/`SnippetRun`/`snippetToMarkdown` in `src/app/(hub)/docs/tree-model.ts`.
- **Space page** (`src/app/(hub)/spaces/[slug]/page.tsx`) renders **8 config/help sections before content** — content (docs tree + files) is dead last.
- **File browsing** is two components: `SpaceDocsTree.tsx` (a real recursive tree of *projected docs*, **expanded by default** — test asserts `aria-expanded="true"`) and `SpaceFilesView.tsx` (the git-tree "files" view, actually a **flat list of full path strings**, no tree). Neither scales to 100 files.
- **Catalog** works (32 pure-logic tests pass). **No "Audience" column exists in code** — auto-mode renders the *union of docs' frontmatter keys* as columns (`unionFields`, `projection.ts:70`), so an "Audience" column means the space's `.md` files carry an `audience:` frontmatter key (data), and/or the owner is viewing **un-redeployed staging**. The **directory picker** (`directoriesInSpace`, `source.ts:83-116`) enumerates *every ancestor prefix* of every doc path as a flat pill list (a doc at `reports/2026/07/x` adds 3 pills) — the "lots of directories" noise. `/help#catalog` has one stale line ("catalog tables retained but dormant" — false after Slice 6).

## Decisions

- **D1 (share type).** Body `~17px`, `line-height ~1.6`, measure `~760px`; scale headings/table/code proportionally. Centralize the md/html width into **one shared constant** consumed by the article + all chrome, killing the scattered literals. `.md-partner` only (operator/hub reader untouched unless it visibly shares the problem).
- **D2 (search).** A **global search box in the hub header** (`layout.tsx` top bar) → a new **`/search?q=` RSC page** that calls `searchDocs` with `scopeForPrincipal(principal)` and renders results (title → doc, path, highlighted snippet via the existing `splitSnippet` helper). Name-search is primary (title weight A already ranks it above body); content search comes free. **No backend change.** A title-only mode + a header live-dropdown are deferred (YAGNI).
- **D3 (space page → tabs).** Restructure into **two tabs: Content (default) and Settings**. Content hosts the unified file explorer (D4) + the authoring actions (New doc / Upload). Settings holds visibility, push policy, GitHub mirror, invite, members, setup prompt. Proposals stay on Content (they act on `main`). The individual panels are self-contained and move wholesale — no internal changes.
- **D4 (unified file explorer).** One collapsible tree of **all committed files** (from `listSpaceFiles`), **folders collapsed by default**. A doc leaf links to its rendered page (`/docs/<slug>`); a non-doc leaf links to the raw file route. Replaces both `SpaceDocsTree` and `SpaceFilesView` on the space page. Tree derived client-side from each entry's `path` (same folder-splitting pattern as `deriveFolders`) — no data/boundary change. Keep `buildDocTree`/`SpaceDocsTree` if `/docs` still uses them; only the space page swaps to the unified explorer.
- **D5 (catalog clarity).** (a) A **help explainer** at the top of `CatalogProjectionClient.tsx` — what a catalog is (a live read-only render of a directory's frontmatter; edit = edit the file + push), the **directory picker vs field filter** distinction, the crux line **"columns are your docs' frontmatter keys — an unfamiliar column means a doc has that key"** (this directly explains the Audience column), and schema mode in one line. (b) **Directory picker** no longer sprays every ancestor prefix flat — show a **collapsed/tree or top-level-first** control so deep spaces stay tidy. (c) Fix the stale `/help#catalog` line.
- **D6 (no backend/boundary work).** Every slice is presentational. The catalog "audience column" needs **no code fix** — it's frontmatter data and/or the pending **staging redeploy** (already the standing Slice-0 operator action).

Reading measure widened to **740px effective** (article `maxWidth` 680 → 788, same 24px×2 padding, border-box). Centralized into a new `src/app/s/[token]/reader-width.ts` exporting `MD_READER_WIDTH = 788` / `HTML_READER_WIDTH = 1100` (html untouched), imported by `src/app/s/[token]/page.tsx` and `src/app/s/[token]/[slug]/page.tsx` for every article/header/banner/divider literal — plus `SuggestEdit.tsx` and `ShareComments.tsx` (not in the original survey's line list, but they hardcode the same md measure for their own sections; left un-centralized they'd visually drift from the widened article). `pnpm typecheck` / `pnpm build` / `npx vitest run src/app/s` all green, no test changes needed (no test asserted the old pixel values).

- **S5 (2026-07-07).** `src/app/(hub)/catalog/CatalogProjectionClient.tsx`: added a `CatalogHelp` collapsible explainer (defaults open) under the header — covers "live read-only render, edit the file + `git push`", the crux line that a column is a doc's frontmatter key (directly explaining a stray "Audience" column), the directory-picker-vs-field-filter distinction, and schema mode in one line. Directory picker rebuilt as a **client-side collapsed tree**: `source.ts`/`directoriesInSpace` untouched (still returns every ancestor prefix, so any directory stays independently selectable — e.g. by a saved/shared `?dir=` link) — a new `buildDirTree` folds that flat list into a `DirNode` tree in the client component, and `DirectoryTree` renders top-level directories first with a ▸/▾ toggle to reveal nested ones, root always expanded. - **S2 (2026-07-07).** `src/app/(hub)/spaces/[slug]/page.tsx` restructured into two tabs via a new **`SpaceTabs.tsx`** client shell. The page stays an RSC: it builds a **Content group** (author panels + proposals + the file explorer) and a **Settings group** (visibility, push policy, GitHub mirror, invites, push help, setup prompt, members) as server-rendered JSX and passes them to `SpaceTabs` as `content` / `settings` props — the sanctioned "slot" pattern (Server Components rendered ahead of time, handed to a Client Component as rendered output). `SpaceTabs` keeps **both** groups mounted and flips the `hidden` attribute on switch, so nothing re-fetches and SSR is fully preserved; default tab = **Content**. **WHO sees each panel is unchanged** — every panel kept its exact gate (`canManage` config controls with read-only fallbacks, `canManage`-only invites, `myMembership`-only setup prompt, `canSeeProposals`-gated proposals); only WHERE (which tab) moved. A `hasSettings = isAdmin || myMembership != null` prop gates the Settings tab: a viewer who is neither admin nor member (only reachable if the page's membership gate is ever relaxed for public spaces) gets **no** Settings tab/panel, never newly exposing anything. `SpaceTabs.test.tsx` proves Content-default, that the Settings panel holds config (hidden until switched), and that `hasSettings=false` renders no Settings tab or panel.

- **S3 (2026-07-07).** New **`SpaceFileExplorer.tsx`** client component — ONE collapsible tree of all `listSpaceFiles` entries, **folders COLLAPSED by default**, doc leaf → `/docs/<slug>`, non-doc leaf → `/api/spaces/<slug>/raw/<path>`. Backed by new pure helpers **`deriveFileFolders` + `buildFileTree`** in `src/app/(hub)/docs/tree-model.ts` (mirror the `deriveFolders`/`buildDocTree` shape but split on the FULL file path — last segment is the file — and default folders **collapsed**: a folder reveals children only when `expanded[path] === true`; builder sorts a copy by path, never mutates input). Replaced `SpaceDocsTree` + `SpaceFilesView` on the space page — both were used ONLY there (grep-confirmed), so both components **and** `SpaceDocsTree.test.tsx` were removed; `buildDocTree`/`deriveFolders` stay (still used by the `/docs` route + re-exported by `view-model.ts`). **⚠ Raw-files boundary preserved exactly:** the page still computes `canSeeRawFiles = canWebAuthor || isAdmin || myMembership` and only feeds the explorer the full tree (incl. non-doc raw files) for that audience; a viewer OUTSIDE the gate is fed a **docs-only** list synthesized from `visibleDocs` (already excludes unpublished for non-admins) via `folder/slug.ext` synthetic paths — so no non-doc raw file, and no unpublished-doc path, ever reaches a wider audience than before. (This fallback is currently unreachable — the page's line-69 membership gate already forces `isAdmin || myMembership` — but is kept as a defensive boundary.) `SpaceFileExplorer.test.tsx` proves: folders start `aria-expanded="false"` with children hidden, expand-on-toggle reveals the nested leaf, doc→rendered / raw→raw-route links, and the BOUNDARY case (a docs-only feed renders **no** `/api/spaces/…/raw/…` link or "raw" badge). `tree-view-model.test.ts` adds `buildFileTree`/`deriveFileFolders` unit tests (collapsed-default shape, recursive count, expand semantics, no-mutation). `pnpm typecheck` / `pnpm build` (`/spaces/[slug]` in the manifest) / `npx vitest run src/app/(hub)/spaces src/app/(hub)/docs/tree-view-model.test.ts` (44 tests) all green.

- **S4 (2026-07-07).** New `src/app/(hub)/docs/SnippetLine.tsx` — a presentational component over the existing `splitSnippet` (`tree-model.ts`): renders each run as a React text node inside a `<span>` (plain) or `<mark>` (matched, tinted with `var(--accent-ring)`), so it never touches `dangerouslySetInnerHTML` — a doc body that looks like markup (`<img onerror=…>`) is escaped by React like any other text. Accepts either the raw delimiter-encoded `snippet` string or pre-split `runs`. `src/app/(hub)/docs/snippet.test.tsx` previously asserted XSS-safety against a hand-rolled facsimile of the not-yet-built component; rewired it to render the real `SnippetLine` (adjusted the `<mark>` assertion to tolerate the inline `style` attribute) and added two small cases (empty snippet → renders nothing; `runs` prop path). New `src/app/(hub)/search/page.tsx` (RSC, `export const dynamic = "force-dynamic"`): resolves `searchParams` (a `Promise` in this Next version — awaited, mirroring `catalog/page.tsx`), resolves `principal`/`scope` the identical way `GET /api/docs?q=` does (`getPrincipal` → `scopeForPrincipal`), and calls `searchDocs(q, { includeUnpublished: principal.kind === "admin", scope })` — no new boundary code, scoping is 100% delegated to the existing service. Blank/whitespace `q` renders a friendly empty-state prompt (no query yet, no DB call); a non-empty `q` with zero hits renders a "no results" state; otherwise a bordered result list (title → `/docs/<slug>`, muted `spaceSlug/path/slug` line, `SnippetLine` for the highlighted snippet) styled like the existing `/spaces` list. Also added a "Search" entry to `HubNav.tsx` (no test constrained its link list). `pnpm typecheck` / `pnpm build` (new `ƒ /search` route in the manifest) / `npx vitest run "src/app/(hub)/docs/snippet.test.tsx"` (9 tests) all green.
