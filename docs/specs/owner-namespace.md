# Desk — Owner-namespaced spaces: stable user handles, composite (owner, slug), `/spaces/<owner>/<slug>` (design)

> **Status: DRAFT — pending owner review (2026-07-08).** Turns Desk's flat global space namespace into a true multi-tenant one (`architecture.md`: "N owners × spaces, symmetric"), so two owners can each own a `growth-reports`. Grounded in a read-only survey of `main@98757d6`. **AUTH-SENSITIVE + DATA-SENSITIVE:** it changes how spaces resolve (read + git write boundary) and moves canonical bare repos on disk. Landing posture: branch, atomic slices, full suite + build + typecheck green, **STOP for review**; the repo migration gets a backup + dry-run before it runs anywhere real.

## Why

1. **No real owner identity exists.** The `<owner>` in the git URL is `ownerSlugForUser()` (`src/lib/spaces.ts`), derived from the email **local-part** (`lucas@example.org` → `lucas`), falling back to token name / `u<id>`. It is **not unique** (`lucas@a.com` and `lucas@b.com` both → `lucas`) and **not stable** (recomputed from the current email, and `users.email` is mutated — `users.ts:508–516` repoints the primary email when one is removed). You cannot build a reliable namespace on it.
2. **Latent repo-orphan bug.** The on-disk bare-repo path is `bareRepoPath(ownerSlugForUser(...), slug)` (`repoPathForSpace` in `web-author.ts` / `proposals-service.ts` / `mirror.ts` / `materialize.ts`). Because the owner segment is re-derived from the current email, **changing a user's primary email changes their spaces' repo paths → the existing bare repos are orphaned** (history appears lost). Decoupling the path from email fixes this.
3. **Flat global namespace.** `spaces.slug` is globally unique (`schema.ts:120`), so only one `growth-reports` can exist instance-wide; the git URL carries `<owner>` but the web/API resolve by the globally-unique slug alone — the owner segment is a validated label, not a namespace. This contradicts the documented multi-tenant model and blocks two owners sharing a slug.

## Decisions

- **D1 (user handle).** New column `users.handle` — a **stored, stable, unique, URL-safe** slug (`^[a-z0-9][a-z0-9-]*$`, length ≤ 39). Backfilled for existing users from the email local-part (or `tokenName`), de-duplicated with a `-2/-3…` suffix on collision. Assigned on user creation the same way. **Admin-editable** (uniqueness enforced; a rename is a real operation — see D3). This replaces `ownerSlugForUser` as the owner identity for URLs **and** repo paths.
- **D2 (composite space uniqueness).** Drop the global unique on `spaces.slug`; add `unique(owner_user_id, slug)`. Two owners may each own `growth-reports`. Slug validation unchanged (`^[a-z0-9][a-z0-9-]*$`).
- **D3 (repo path decoupled from email).** `repoPathForSpace` derives the path from the stored **handle** + slug (never the email), so email changes never orphan a repo. A **handle or slug rename** atomically moves the on-disk bare-repo dir within the same transaction/operation. A one-time boot migration re-points existing repos from the email-derived path to the handle-derived path (usually identical, since the handle backfills from the same local-part; the migration only moves the ones that differ). *Considered and rejected:* keying repos on immutable `spaceId` (fully decoupled, rename never touches disk) — cleaner in theory but loses on-disk browsability and forces migrating **every** repo; the handle-derived path migrates only the few that differ and keeps `DESK_DATA_DIR` human-readable. Revisit if renames become frequent.
- **D4 (owner-shaped URLs everywhere).** Web `/spaces/<handle>/<slug>`; API `/api/spaces/<handle>/<slug>/*`; git `/api/git/<handle>/<slug>.git` (already owner-shaped — now the segment is the stable handle). Canonical resolution: `handle → userId`, then `(userId, slug) → space`. `getSpaceBySlug(slug)` becomes `getSpace(handle, slug)` (~20 callers).
- **D5 (redirects preserve existing links).** The legacy single-segment **web** route `/spaces/<slug>` resolves the slug: **exactly one** space with that slug → **301** to `/spaces/<handle>/<slug>`; **ambiguous** (only possible once a future collision exists) → 404; none → 404. This keeps every existing link (e.g. the external project's `/spaces/growth-reports`) working. Legacy `/api/spaces/<slug>/*` does **not** 301 (a redirect on a POST would drop the body agents/CLI send) — it **resolves in place** by unique slug during a deprecation window, and returns a clear `409/400 "ambiguous — qualify with <owner>/<slug>"` if a collision exists. Same rule for MCP bare-slug args (D6).
- **D6 (MCP/agent surface).** MCP tools that take a `space` argument (`publish_doc`, `create_directory_share`, `set_space_member`, `create_invite`, proposals, mirror, …) accept an **owner-qualified** `handle/slug`; a bare `slug` still resolves when unambiguous and errors clearly when ambiguous. `whoami` surfaces the caller's handle. `/help` + the README tool table updated.
- **D7 (docs out of scope).** `/docs/<slug>` is unchanged — doc slugs are globally-unique opaque ids with no collision problem. Readable `/{owner}/{space}/{path}` doc URLs stay deferred (per the doc-identity spec), a separate concern.

## Slices

Two phases. **Phase A (S1–S2)** introduces stable handles and fixes the repo-orphan bug — shippable on its own, no URL/behavior change for users. **Phase B (S3–S5)** delivers the multi-tenant namespace. Order is strict (each builds on the last). Every slice: full `npx vitest run` + `pnpm build` + `pnpm typecheck` green, atomic commits, **STOP for review**.

### Phase A — stable handles (safe foundation)

- **S1 — `users.handle` primitive.** Hand-authored migration: add `users.handle text` + unique index; backfill all existing users (local-part/tokenName → slugify → de-dup with `-N`); NOT NULL after backfill. New-user creation assigns a handle. Admin edit path (`PATCH /api/users/[id]` or the users UI) with uniqueness + format validation. `whoami`/user views expose `handle`. Tests: backfill determinism + de-dup, format/uniqueness enforcement, admin-only edit. **No URL/repo change yet.**
- **S2 — repo path via handle (fixes the orphan bug).** Replace `ownerSlugForUser` usage in `repoPathForSpace` (and `bareRepoPath` callers in `web-author.ts`, `proposals-service.ts`, `mirror.ts`, `materialize.ts`, the git route, `import.ts`) with the stored **handle**. One-time boot migration (`instrumentation.register`, following `backfillShareSpaceIds`/`materializeDbOnlyDocs`): for each space, if the email-derived legacy path exists and differs from the handle-derived path, **move** the bare repo dir (idempotent; log every move; skip when already correct). **Retire `ownerSlugForUser`.** Tests: path derives from handle not email; a simulated email change does NOT change the path; migration moves a mismatched repo and is a no-op on re-run. **⚠ canon data — dry-run/log first, backup `DESK_DATA_DIR` before running on staging/prod.**

### Phase B — the namespace

- **S3 — composite key + resolution refactor (auth-sensitive core).** Migration: drop `spaces.slug` global unique; add `unique(owner_user_id, slug)`. `getSpaceBySlug(slug)` → `getSpace(handle, slug)` across ~20 callers; `createSpace` uniqueness check becomes `(owner, slug)`. **Rewrite `resolveSpaceRole`** (the git write boundary) to resolve `(handle→userId, slug)→space` instead of global-slug + owner-match. Exhaustive boundary tests: two owners with the same slug stay isolated (member of A ≠ access to B); git clone/push authorizes against the right `(owner, slug)`; wrong-owner/wrong-handle → uniform 404; the full read matrix (admin/member/non-member/public/share/anonymous) holds per owner.
- **S4 — route restructure + redirects.** Web `/spaces/[slug]` → `/spaces/[owner]/[slug]`; API `/api/spaces/[slug]/**` → `/api/spaces/[owner]/[slug]/**` (every sub-route: docs, raw, members, invites, mirror, proposals, deploy-key). Legacy single-segment web + API routes become redirect/deprecation handlers per D5 (unique→301, ambiguous→404). MCP `space` args accept `handle/slug` (D6). Git URL emission (`git-url.ts`) uses the handle. Tests: canonical routes resolve; legacy `/spaces/<slug>` 301s while unique and 404s when ambiguous; MCP owner-qualified + bare-slug resolution.
- **S5 — links, catalog, projections, sweep.** Update every `/spaces/` link (~16 UI files: `HubNav`, `spaces/page.tsx`, all space panels, `docs/[slug]` back-links, `help`), the catalog `?space=` param (now needs owner qualification), the setup-prompt/push-help git URLs, and any breadcrumb. Confirm directory shares (space-scoped by `space_id` since fix-pass Slice 1 — id-based, no change) and doc URLs (`/docs/<slug>`, unchanged) are unaffected. Full boundary/build/typecheck sweep; update README + `architecture.md` (§3 multi-tenant now real) + AGENTS.md; append Outcomes.

## Testing & verification

- **Boundary-class tests are mandatory** (this is the sacred read + git-write boundary): two owners same slug isolated; per-owner read matrix (admin/member/non-member/public/share/anonymous → uniform 404 on miss); git clone/push authorizes against `(owner, slug)`; handle rename moves repo + keeps access; email change never orphans a repo.
- **Browser verification** (per `verification-before-frontend-completion`) for the route/link changes: navigate to `/spaces/<owner>/<slug>`, confirm a legacy `/spaces/<slug>` 301s, links resolve.
- The repo migration (S2) is validated on real seed data with a **dry-run/log pass** before an actual move; `DESK_DATA_DIR` backed up first.

## Deferred / out of scope

Readable doc URLs `/{owner}/{space}/{path}` · self-serve (non-admin) space creation · user-editable handles (admin-only for now) · immutable-id repo paths (D3 alternative) · changing the doc opaque-slug scheme.

## Landing

Order **S1 → S2 → S3 → S4 → S5**, each committed atomically with full suite + build + typecheck green, then **STOP for review** (S2 data-sensitive, S3 auth-sensitive). Never force-push. Hand-authored migrations. Phase A (S1–S2) is independently shippable and worth landing/reviewing before Phase B. Redeploy staging after Phase A and after Phase B.

**Overall acceptance:** two owners each create `growth-reports`; both resolve correctly at `/spaces/<owner>/growth-reports` (web + API + git clone/push), isolated by the access boundary; the external project's legacy `/spaces/growth-reports` 301-redirects to the right one; a user's email change no longer orphans their repos.

### S1 — `users.handle` primitive (landed)

Added a **stored, unique, URL-safe `users.handle`** (`^[a-z0-9][a-z0-9-]*$`, ≤ 39) — the real owner identity later slices use for repo paths + URLs, replacing the broken email-derived `ownerSlugForUser` (which stays in place until S2 retires it). **No URL/route/repo-path change** — this slice adds the primitive only.

- **Schema + migration `0023_user_handle`** — `ALTER TABLE users ADD COLUMN handle text` + a **unique index** (`users_handle_idx`). Kept **nullable for now** on purpose: Postgres allows multiple NULLs under a unique index, so existing rows sit at NULL until the boot backfill assigns them; every creation path assigns a handle going forward, so NULLs exist only transiently pre-backfill. Hand-authored SQL + a journal entry (idx 23), per the broken-`drizzle-kit-generate` convention (no snapshot, matching 0018–0022).
- **Shared derive+dedup** lives in **`src/lib/user-handle.ts`** as the single source: `deriveHandleBase(tokenName ?? email-local ?? u<id>, id)` → `slugifyHandle` → `dedupeHandle(base, taken)` (`lucas`, `lucas-2`, `lucas-3`…, length-capped). The **boot backfill** (`backfillUserHandles`, wired into `instrumentation.register` after the existing backfills) walks users **id-ascending**, seeds the taken-set from already-assigned handles, and assigns each NULL row — idempotent (skips assigned rows; every UPDATE guarded by `handle IS NULL`; re-run is a no-op). The **creation helper** (`assignUserHandle(tx, userId)`) runs inside each user-insert transaction; the unique index is the concurrency guard.
- **Every creation path assigns a handle:** `createUser`, access-request accept, invite accept, first-login `bootstrapAdmin`, the `system` reserved user, and the dev-mode `dev-admin`/`dev-member` stubs.
- **Admin edit:** `PATCH /api/users/[id]` accepts `handle` (admin-only, mass-assignment-guarded); `setUserHandle` enforces format (**400** on invalid) + uniqueness (**409** on collision). A rename stores the new handle only — no repo move yet (that's S2/S3).
- **Exposed:** `handle` on the `whoami` MCP tool output, on `UserListItem` (so `listUsers`/`getUserById` carry it), and in the admin Users table (an `@handle` line under the name with an inline edit control mirroring the existing display-name editor).
- **Tests:** backfill determinism + de-dup (three `lucas` → `lucas`/`lucas-2`/`lucas-3`), idempotent re-run, agent (tokenName) + no-identifier (`u<id>`) fallbacks, de-dup against a pre-assigned handle; pure-helper unit tests; admin-edit format/uniqueness/admin-only (400/409/403); creation assigns a unique handle. Full `npx vitest run` (1613) + `pnpm build` + `pnpm typecheck` green.

### S2 — repo path via handle, fixes the orphan bug (landed)

Decoupled the on-disk bare-repo path from the mutable email: it now derives from the stable **`users.handle`** (decision D3), so an email change can no longer orphan a space's repo. A one-time boot migration re-points existing repos from the legacy email-derived path to the handle path. **No URL/route change** — the git URL owner segment + `resolveSpaceRole`'s URL matching stay email-derived until Phase B (S3/S4).

- **One shared repo-path helper.** New module **`src/lib/space-repo-path.ts`** exports `spaceRepoPath(space)` (accepts anything with `{ ownerUserId, slug }`). It loads the owner's `users.handle` and returns `bareRepoPath(handle, slug)`. If the handle is somehow NULL (a pre-backfill race, or a user made outside the assign-on-create paths) it **assigns one on read** (`assignUserHandle`) — it **never** silently falls back to the email — and throws a clear error only if the owner row is gone. This replaces the **copy-pasted** `repoPathForSpace` that lived in `web-author.ts` / `proposals-service.ts` / `mirror.ts` (local fns) and the inline `ownerSlugForUser` + `bareRepoPath` derivations in `materialize.ts`, `import.ts`, the git transport route, and the `raw` / `reindex` / `docs` / catalog-source read paths — all now call the single helper.
- **Boot migration `migrateRepoPathsToHandle()`** (same module). For each space it computes `legacyPath = bareRepoPath(ownerSlugForUser(currentOwner), slug)` and `newPath = bareRepoPath(handle, slug)`, then MOVES the dir (`fs.rename`, after `mkdir -p` of the parent) **only** when the legacy repo exists, the paths differ, and the target does **not** exist. **Idempotent + non-clobbering:** `legacy===new` → skip (the common case, since handles backfill from the same email local-part); no repo at legacy (never created, or already moved) → skip; **both exist → logged conflict, left untouched (never clobber)**; a re-run finds nothing at the legacy path → skip. Every intended move / move / skip / conflict logs a `[migrate-repo-path] …` line so a boot reads like a dry-run even as it acts.
- **`instrumentation.register` reordered** to the strict sequence the handle-keyed paths require: `ensureBootstrapAdmin → backfillUserHandles → migrateRepoPathsToHandle → materializeDbOnlyDocs → backfillPolicyHooks → backfillShareSpaceIds`. (S1 had wired `backfillUserHandles` LAST; materialization now writes to the handle-derived path, so handles must be assigned and repos moved first. Policy-hooks + share-space_id are order-independent and sweep the final on-disk layout last.)
- **`ownerSlugForUser` retired from every repo-path derivation.** Its only remaining use in a repo-path context is inside `migrateRepoPathsToHandle` (to compute the LEGACY path to move away from). It still backs the *URL* owner segment (`ownerSlugForSpace` → `resolveSpaceRole` matching, git-URL display, `listSpacesForView`) — those are unchanged in Phase A and get rewired in S3/S4. (`indexer.reindexSpaceBySlug` takes an explicit `ownerSlug` arg and has no callers — left as-is.)
- **Tests (`src/lib/space-repo-path.test.ts`):** `spaceRepoPath` is invariant across an email change (the bug-fix proof) and keys on the handle, not either email local-part; a NULL handle is assigned-on-read (not email-derived). Migration: a mismatched repo is **moved with content intact** (verified via a fresh clone at the new path); a re-run is a no-op; a space already at the handle path is skipped; a pre-existing target is never clobbered (conflict); a mixed run moves only the mismatched space. Full `npx vitest run` + `pnpm build` + `pnpm typecheck` green.

### S3 — composite (owner, slug) key + resolution refactor (auth-sensitive core; landed)

Made the space namespace **multi-tenant** (decision D2): two owners may each own `reports`, isolated by the sacred read + git-write boundary. This is the AUTH-SENSITIVE core — it changed the git write boundary's resolution and the space uniqueness key. **No web/API route was switched to owner-qualified resolution yet** (that is S4); `getSpaceBySlug` stays a transitional resolver.

- **Migration `0024_spaces_composite_owner_slug`** — **DROP** the global `spaces_slug_unique` constraint; **ADD** a composite unique index `spaces_owner_slug_idx` on `(owner_user_id, slug)`. Slug FORMAT validation unchanged (`^[a-z0-9][a-z0-9-]*$`). Hand-authored SQL + journal entry (idx 24), per the broken-`drizzle-kit-generate` convention (no snapshot, matching 0018–0023). Schema: `spaces.slug` loses `.unique()`, gains the composite `uniqueIndex` in the table callback. Existing rows had globally-unique slugs, so no `(owner, slug)` pair collides — the index builds clean.
- **New canonical resolver `getSpace(handle, slug)`** (`src/lib/spaces.ts`) — `handle → users.id` (via `users.handle`, case-insensitive), then `(ownerUserId, slug) → space`. Returns **null** (no leak, no throw) on an unknown/blank handle OR when that owner has no such slug. A sibling `getSpaceByOwner(ownerUserId, slug)` does the direct `(owner, slug)` lookup (the form `getSpace` calls after turning a handle into a user id, and the one `createSpace` uses for its per-owner dup pre-check). This is the resolver every owner-qualified surface (git write boundary now; routes in S4) resolves through.
- **`resolveSpaceRole` rewritten** (the git write boundary) — it now resolves the git URL's `<owner>` segment as a **handle** via `getSpace(ownerSegment, slug)` → then the caller's `space_members` role on the RESOLVED space, instead of looking up the globally-unique slug and matching the segment against a re-derived owner slug. Because `handle === ownerSlugForUser` for existing users, existing git remotes keep resolving; but `/api/git/alice/reports.git` and `/api/git/bob/reports.git` now resolve to DIFFERENT spaces, and a token with a role on A's space is **denied (uniform 404)** on B's (no membership there). **Every failure is fail-closed → null → the existing uniform 404:** unknown/blank token, revoked token, inactive user, unknown handle, that owner having no such slug (incl. a *different* owner's same-slug space), no membership, reader-pushing. Reader/writer/owner rank logic preserved.
- **The git write path no longer re-resolves by the (now-ambiguous) slug.** `authorizeGit`'s `ok` decision carries the resolved `spaceId`; the git route (`route.ts`) loads the space by **id** (`getSpaceById(decision.spaceId)`) not `getSpaceBySlug`, and passes `spaceId` to `reindexSpaceByDisk` (which gained an owner-correct `opts.spaceId` path) so a push re-indexes the EXACT authorized space — never a different same-slug owner's. `web-author` passes `space.id` the same way.
- **`createSpace` uniqueness → `(owner, slug)`.** Ensures the owner has a stable `users.handle` (assign-on-read, idempotent — a no-op in production where every creation path already assigns one; this is what makes a freshly created space git-reachable in tests that seed users directly). The pre-check is now per-owner (`getSpaceByOwner(ownerUserId, slug)`), and the unique-violation catch is backed by the composite index. **Two different owners creating the same slug both SUCCEED; the same owner twice → "slug already in use".**
- **`getSpaceBySlug(slug)` is TRANSITIONAL + ambiguity-guarded (D5).** It selects up to two rows for the slug: **exactly one → return it** (the common single-owner case, unchanged behaviour); **zero or more-than-one → null** (fail-closed — an ambiguous slug is not-found; it never returns an arbitrary winner). The ~19 not-yet-owner-qualified callers keep working while any slug is single-owner; S4 rewrites them to `getSpace(handle, slug)`. (Note: the transitional slug-based `setSpaceMemberRole` / `createDirectoryShare` likewise no-op / pick deterministically only while a slug is unique — expected until S4.)
- **Boundary tests (exhaustive; the point of the slice):**
  - *`src/lib/spaces.test.ts`* — `getSpace(...)`: two owners `alice`/`bob` each `createSpace("reports")` both succeed → `getSpace("alice","reports")` and `getSpace("bob","reports")` return DIFFERENT spaces (right `ownerUserId`); case-insensitive handle; unknown handle / that-owner-has-no-such-slug → null; `getSpaceByOwner` isolation; `getSpaceBySlug` returns null while `reports` is ambiguous and resolves again once one remains. `createSpace`: same-slug-different-owner both OK + per-owner dup still rejected; owner gets a handle. `resolveSpaceRole` two-owner isolation: owner tokens resolve to the RIGHT `space.id`; a **writer on alice/reports is denied on bob/reports**; bob's owner token denied on alice/reports; unknown handle → null.
  - *`src/lib/git/auth.test.ts`* — `authorizeGit` two-owner matrix: each owner's token authorizes ONLY their same-slug space (asserts the resolved `spaceId`); alice denied on bob/reports and vice-versa; a **writer on alice/reports pushes there but is 404 on bob/reports**; unknown handle segment → denied.
  - *`src/lib/docs.test.ts`* — two same-slug owners, space-scope READ matrix holds independently: PRIVATE same-slug (each owner's member sees only THEIR space; cross-owner + non-member + anonymous fail-closed; admin sees both); **same slug OPPOSITE visibility** (alice's public `shared` visible to an outsider, bob's private `shared` not — visibility is per-space, not per-slug; unlisted third case); **SHARE axis** — a directory share bound to alice's space id never resolves bob's same-slug-space doc (`resolveShareDoc` space guard).
  - *`src/app/api/git/[...path]/clone-push-e2e.test.ts`* — live git over a real socket: lucas pushes into the OWNER-CORRECT `e2e` (bob's same-slug `e2e` stays empty — re-index isolation by resolved id); **cross-owner: lucas's token is REJECTED cloning bob/e2e; bob's token clones bob/e2e; bob rejected on lucas/e2e**.
- **All green:** `npx vitest run` **126 files / 1641 tests**; `pnpm typecheck`; `pnpm build`.

### S4 — route restructure + owner-qualified web/API/MCP + legacy redirects (landed)

Made the WEB + API + MCP surfaces **owner-qualified** (decision D4) and preserved every legacy single-slug link during a deprecation window (D5/D6). The access boundary itself was proven in S3; S4 switches the ~16 route callers to resolve through it and adds the legacy-URL shim.

- **The `[slug]` vs `[owner]/[slug]` routing conflict (Next 16).** Next errors on two differently-named dynamic segments at the same level, so `spaces/[slug]/` and `spaces/[owner]/[slug]/` can't be siblings. Resolution: **rename** the existing route dirs `spaces/[slug]` → `spaces/[owner]/[slug]` (web) and `api/spaces/[slug]/**` → `api/spaces/[owner]/[slug]/**` (API) as the ONLY canonical shape, and handle the legacy single-segment shape in the **proxy** — NOT as a sibling route. Cited `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md`: (a) the `middleware` file convention is **deprecated → renamed `proxy`** in v16 and (b) **"Proxy defaults to the Node.js runtime"** — which is what lets the legacy shim do the DB lookup (`slug → owner handle`) it needs; an Edge middleware couldn't run `postgres-js`. So `src/middleware.ts` → **`src/proxy.ts`** (`export async function proxy`), keeping its existing host-routing job and adding the legacy space-URL job. `NextResponse.rewrite` (per the same doc) preserves method + body, which is why the API legacy path rewrites rather than 301s.
- **Canonical route tree.** Web: `src/app/(hub)/spaces/[owner]/[slug]/page.tsx` (+ its colocated panels). API: `src/app/api/spaces/[owner]/[slug]/**` — `route.ts` (PATCH), `docs`, `raw/[...path]`, `members`, `invites`, `mirror` (+ `now`, `deploy-key`), `proposals` (+ `[name]/{accept,reject,diff}`), `reindex`. Each handler's `params` gained `owner` and now resolves via **`getSpace(owner, slug)`** (the S3 canonical resolver) instead of `getSpaceBySlug(slug)` — 16 route callers switched; a wrong owner/handle → null → the existing uniform 404.
- **Legacy shim in the proxy (`src/lib/legacy-space-route.ts` → `planSpaceRoute(pathname)`).** Structural pre-filter keeps canonical traffic DB-free; only legacy-SHAPED paths hit the DB.
  - **Web** `/spaces/<slug>` (one segment): resolve the slug → a UNIQUE owner → **301** to `/spaces/<handle>/<slug>` (preserves every bookmark, incl. the external `/spaces/growth-reports`); ambiguous / unknown → pass → Next's natural 404 (there is no 1-segment web route). Canonical `/spaces/<owner>/<slug>` (two segments) → pass, no DB.
  - **API** `/api/spaces/<slug>[/<subresource>…]`: a redirect would drop a POST body, so resolve the slug → owner handle and **rewrite IN PLACE** to `/api/spaces/<handle>/<slug>/…`; ambiguous → **409** "qualify with <owner>/<slug>"; unknown → pass → 404. Legacy-shape detection = a bare slug OR `<slug>/<reserved>` where `<reserved>` ∈ {docs,invites,members,mirror,proposals,raw,reindex}; canonical 2-/3-segment paths whose 2nd segment is NOT reserved pass with no DB. The reserved-word edge (a space literally named e.g. `docs`) is disambiguated by a cheap handle check: if the first segment is a known handle the path is canonical → pass (so `/api/spaces/alice/docs` reaches alice's `docs` space, while `/api/spaces/docs/members` still rewrites for a space slugged `docs`).
- **MCP owner-qualification (D6).** New **`resolveSpaceArg(arg)`** (`src/lib/spaces.ts`): an owner-qualified `handle/slug` resolves the exact owner via `getSpace`; a bare `slug` resolves only when a SINGLE owner has it and returns a clear ambiguity error otherwise. Every space-taking tool (`publish_doc`, `create_directory_share`, `set_space_member`, `create_invite`, `list_proposals`, `decide_proposal`) resolves through it; arg descriptions + the README MCP tool table updated to `handle/slug`. (`whoami` already surfaces the caller's handle since S1; there is no separate MCP `/help` command in this codebase.)
