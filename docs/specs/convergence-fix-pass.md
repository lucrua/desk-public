# Desk — Convergence fix-pass: git-truth writes, share-boundary fix, tiered client editing, GitHub mirrors, agent loop (build spec)

> **Status: DRAFT — pending owner review (2026-07-03).** Grounded in a four-agent read-only survey of `main@46de1d9`. This spec is the consolidation outcome: it fixes what contradicts the model, closes the two external write loops (clients and agents), and deletes what the consolidation already retired. It deliberately builds **nothing speculative** — every slice either fixes a found defect or completes a loop the owner's proof case (acme-growth Amplitude reports) needs.
> **Model:** inherits `docs/architecture.md` (space = git repo = boundary; truth = the file; Postgres = derived projection; publish = push). The organizing principle of this whole spec: **every content write converges on a git commit in the space's repo on Desk; Desk fans out from there.** Reuses: `commitFiles` (web-author W1 primitive), capability links (sha256-at-rest, uniform-404), `push_policy` + proposals (E2), the revisions queue + diff UI, `DESK_TOKEN_KEY` AES-GCM encryption (share-reveal machinery).

## Why (findings this spec answers)

1. **`publish_doc` (MCP) / `POST /api/docs` (REST+CLI) write Postgres only, never git**, and have no `space` param — a NEW doc silently lands in the default `workspace` space: not a file, invisible to a clone, invisible to the target space's members. Violates truth-in-git.
2. **`acceptRevision` → `publishDoc` also writes Postgres only** — accepting a revision updates the doc row while the file in the repo silently keeps the old content. Git and projection drift.
3. **Directory shares are not space-scoped** — `listDocsUnderShare` filters by path prefix with no `spaceId` predicate; same-named folders in two spaces leak through one link. Read-boundary bug.
4. **A share-link visitor can read and comment but has no edit path of any kind** — the owner's tiered-collaboration goal needs an anonymous "suggest edit" on the share surface.
5. **No durability story for canon** — `DESK_DATA_DIR` on one box, no backups (a standing risk flagged in `architecture.md` §11). Owner wants GitHub as the comfort/backup layer, per-space, without bespoke sync.
6. **Deployed staging MCP runs pre-consolidation code** (still advertises retired audience/catalog tools) and **README/architecture still label built features "not built"** (web-author W1, E1/E2).
7. **Gen-1 corpses linger**: dormant `audiences`/`audience_members`/`docs.audience`, dormant P3 `catalog_*` registry + inert auto-linker, vestigial `audience` params on MCP wire schemas, the CLI's non-git `desk sync`/`desk publish`.

## Decisions

- **D-C1 (tiered client editing).** Casual clients suggest edits **anonymously through the share link** (capability-scoped, no account, like comments today). Repeat collaborators use the already-built invite → membership → `push_policy` path. Both tiers' accepts land as **git commits**.
- **D-C2 (one merge machinery).** Git proposals (E2) stay the canon review path for git-capable actors. The DB `revisions` table survives **only** as the queue for browser/share suggestions — and its accept path is rebuilt on `commitFiles`. `publish_doc`/`POST /api/docs` are rebuilt on `commitFiles` with a **required `space`**. `desk sync` and the CLI write commands are retired. After this spec, **no code path writes doc content to Postgres except the indexer projecting git.**
- **D-C3 (source modes).** Per-space `source_mode ∈ {hosted, mirrored}`, **default `hosted`**. `hosted`: Desk is canon; Desk mirror-pushes `main` to a paired GitHub repo (one-way, conflict-free by construction). `mirrored`: GitHub is canon; a GitHub Action forwards pushes to Desk; Desk-originated commits are refused server-side. Invariant, documented everywhere: **every repo has exactly one push target; the other side is read-only.**
- **D-C4 (mirror config placement).** Mirror target + credentials live in **Postgres, owner/admin-settable** — never in-repo, never in a local file. Rule of thumb this encodes: *in-repo files configure how content renders (`.desk.collection.yml`); Postgres configures who can do what and where data flows (members, visibility, `push_policy`, shares, mirrors).* A mirror target is data egress — same trust class as a share.
- **D-C5 (credentials).** One **instance-level fine-grained GitHub PAT** (Contents: Read/Write only), entered once, AES-GCM-encrypted with `DESK_TOKEN_KEY`, write-only (never revealed back). Optional **per-space deploy-key override** for isolation. GitHub App: deferred.
- **D-C6 (dispatch).** No webhooks — the agent has no public interface, and near-real-time doesn't need one. v1: the agent **cursor-polls `list_events(kinds:["card.assigned"])` every 30–60 s** (outbound-only, CI-runner pattern). Optional later: a `wait_seconds` long-poll param on `list_events`. The runner is cron in the agent's container; Desk hosts no runner.
- **D-C7 (fail-closed backfill).** Existing directory shares that can't be unambiguously assigned to one space are **revoked** by the migration, not guessed at.

## Slice 2 — Git-truth write convergence (kills findings 1 + 2)

Everything here funnels into `commitFiles` (CAS on ref tip, throwaway worktree, author = acting principal, committer = Desk) followed by the existing synchronous reindex.

- **`acceptRevision`:** on accept, commit the revision content to the doc's `(space, sourcePath)` on `main` via `commitFiles`, then let the reindex project it (the projection write via `publishDoc` is replaced by the indexer's own path). CAS conflict → re-read tip, retry once, else surface a stale error to the reviewer. Commit author: the proposer label (e.g. `link:<share label>` after Slice 3, or the member handle), committer Desk. **Materialization pre-step (one-time):** any doc row whose `sourcePath` has no corresponding blob in its space repo (legacy `publishDoc`-created rows, incl. the `workspace` space) gets its current version content committed to the repo, so accept-time CAS always has a real base.
- **`publish_doc` (MCP) + `POST /api/docs` (REST):** rebuilt, breaking: required `space` + `path`; content committed via `commitFiles` honoring `push_policy` (owner/admin and direct-mode writers → `main`; proposal-mode non-owner writers → `proposals/<handle>`, surfacing in the existing PR review). Doc-format paths project as docs; other paths land as raw files (same posture as web-author upload). Response: `{slug, url, ref}`. `update_doc` path moves become **rename commits** (doc-identity's `-M` detection preserves the opaque id); owner reassignment stays projection metadata (access config, not content). `unpublish_doc` becomes a file-deleting commit (tombstone follows via indexer). `delete_doc` remains the stage-2 DB cleanup for tombstoned rows.
- **Retire:** CLI `desk sync`, `desk publish`, `desk unpublish` (delete the commands; keep read/share commands for now); the vestigial `audience` param on `publish_doc`'s wire schema and `DocListItem.audience`.
- **Tests:** e2e — MCP `publish_doc` → commit visible in a fresh clone + doc renders; proposal-mode routing; accept-revision → commit in clone + projection matches; materialization migration; rename-via-update_doc preserves slug; CAS conflict paths. Full suite + build + typecheck.

## Slice 4 — Source modes + GitHub mirror-out (durability; kills finding 5)

**Schema:** `spaces.source_mode enum('hosted','mirrored') NOT NULL DEFAULT 'hosted'`; `spaces.mirror_remote_url text NULL`; `spaces.mirror_state jsonb NULL` (`{lastMirroredSha, lastAttemptAt, lastError}`); `spaces.mirror_deploy_key_enc text NULL` (per-space override, private key encrypted); instance settings row for the GitHub PAT (`valueEnc`, AES-GCM via `DESK_TOKEN_KEY`, single row v1, write-only — no reveal endpoint).

**Mirror-out (hosted spaces with a `mirror_remote_url`):** after every successful update of `main` — transport push (post-reindex), web-author commit, proposal accept, revision accept — enqueue a mirror push: `git push <remote> main:main`, credential injected per-invocation (askpass/env; **never written to disk or repo config**), deploy key preferred over PAT when present. In-process queue, exponential backoff, capped retries; failures **never block** the triggering write (same posture as reindex); `mirror_state` surfaces status + a "Mirror now" button in space settings. v1 mirrors `main` only (not `proposals/*`), exactly one mirror remote per space.

**`mirrored` spaces:** no mirror-out; **Desk-originated commits refused server-side** with a clear error (`webAuthorCommit`, revision accept, proposal accept) — Desk renders, shares, comments; content arrives only via git push (the documented GitHub Action: `on: push → git push desk main` with a Desk token secret). Suggest-edit (Slice 3) on a mirrored space: suggestions queue but cannot be accepted on Desk — the review UI says so and shows the diff for manual application upstream. Documented in a new `docs/remotes.md`: the one-push-target invariant, both mode recipes, the Action snippet, and "protect `main` on the GitHub mirror so nobody pushes to the read-only side."

**Settings surface:** space settings (owner/admin only, same gate as `push_policy`/visibility): mode, mirror URL, deploy-key generate/rotate (public key shown for GitHub Deploy Keys paste); instance settings (admin): PAT set/replace/clear.

**Tests:** mirror config gates (owner/admin only; member/anonymous → 404); mirror push fires on all four write paths (local bare "GitHub" remote as fixture) and retries/records failure without failing the write; PAT stored encrypted, never returned by any API; mirrored-mode write-refusal matrix (web-author, revision accept, proposal accept refused; git push still accepted); `source_mode` defaults hosted; migration green.

### Slice 2 — Git-truth write convergence (landed)

**What shipped.** Every production doc-content write now converges on a real git commit in the space's repo; the indexer projects it. `publishDoc` (the low-level service) is retained ONLY as the test-seeding seam (`src/test/db.ts`) — no production path calls it anymore.

- **`acceptRevision`** (`src/lib/revisions.ts`) — accepting a revision commits its content to the doc's `(space, sourcePath)` on `main` via `webAuthorCommit` (role forced to `owner` — an accept is an authoritative merge), then the synchronous reindex projects the new version. The direct `publishDoc` DB write is gone. CAS on the live `main` tip; on a `stale` result it re-reads the tip and retries once, else surfaces `stale` to the reviewer (409 / MCP error). The open→accepted transition + `revision.decided` event are preserved. New `AcceptResult` reasons: `stale`, `error`.
- **MCP `publish_doc`** (`src/lib/mcp/tools.ts`) — breaking rewrite: required `space` + `path` (repo-relative file path); commits via `webAuthorCommit` honoring `push_policy` (owner/admin → `main`; non-owner writer under `proposal` → `proposals/<handle>`). The opaque slug is minted by the projection; returns `{ slug, url, ref }` (slug/url null for a proposal). The vestigial `audience` param (and `slug`/`source_path`/`format`/`base_version_id`) were removed from the wire schema.
- **`POST /api/docs`** — same convergence: required `space` + `path`, routed through `webAuthorCommit`; membership-gated (was admin-only-create). Returns `{ slug, url, ref }`.
- **`POST /api/docs/[slug]/publish`** (owner direct-publish of an existing doc) — routed through `webAuthorCommit` (role `owner`), CAS-with-one-retry on `main`; `canPublishVersion` gate (admin OR doc owner) unchanged.
- **Shared plumbing** — `resolveWebAuthorAccess(principal, spaceSlug)` + `liveMainTip(spaceSlug)` added to `src/lib/web-author.ts` (the read/existence + space-role resolution that MCP + REST callers share, fail-closed).

**Tests.** New `src/lib/slice2-git-truth.test.ts` (13) proves: `publish_doc` → commit visible in a fresh `git clone` + doc renders; proposal-mode routing (writer → `proposals/*`, no main projection); accept-revision → commit in a clone + projection matches; accept reads the LIVE tip (survives a main move); CAS stale rejection; wire-schema requires `space`+`path` and dropped `audience`. New `src/test/git.ts` helper (git detection + throwaway `DESK_DATA_DIR` + repo cleanup + clone-read) isolates every committing suite. Bounded updates to the callers' existing suites (revisions, events, doc-ownership, mcp route, tools, tools-s1, docs route, s1-route, `[slug]/revisions`). Two pre-existing test-data `(space, path)` collisions (an `html-doc` sharing a source path with its `test-doc`/`team-doc` sibling in the same space) were fixed — the DB-keyed `publishDoc` masked them; the projection key `(space, sourcePath)` exposes them.

**Deferred (residual gaps, do-if-clean items 5/6/8 — see report).** `update_doc` path-move stays a DB folder-metadata update (not a git rename commit); `unpublish_doc` stays a DB tombstone (not a file-deleting commit); no boot-time materialization backfill. Rationale: a clean git-rename / delete-commit for a doc that was created by the LEGACY DB-only `publishDoc` (no blob at `main`) needs the materialization backfill first, and both are lifecycle/metadata ops — neither writes doc CONTENT to Postgres, so the finding-1/finding-2 invariant ("no production path writes doc content to Postgres except the indexer") holds without them. Pre-existing DB-only docs materialize lazily on their next accept/direct-publish; until then they render from the projection but are absent from a clone.

### Slice 3 — Tier-1 client editing: suggest-edit on the share surface (landed)

**What shipped.** A share-link visitor (no account — the capability token is the credential) can now propose a full new doc body on a share whose owner enabled edits. It queues as a `revision` the owner reviews with the existing diff UI and **accepts** (→ a git commit via the Slice-2 `acceptRevision` path) or **rejects**. The whole feature mirrors share-comments exactly: per-share toggle, forced identity, uniform-404 on every failure, rate-limited. This opened a NEW unauthenticated write ingress, so it is fail-closed everywhere.

- **Schema (`0020_share_edits_suggest`).** `shares.allow_edits boolean NOT NULL DEFAULT false` (real boolean; the fail-closed sibling of the int `allow_comments`). `revisions.share_id integer NULL REFERENCES shares(id)` (the originating share; null for staff proposals) + `revisions.proposer_label text NULL` (the FORCED `"link:<label>"` display label; null for staff). Hand-authored + a `_journal.json` entry (drizzle-kit generate is broken — project convention).
- **Public endpoints.** `POST /api/s/[token]/suggest` (doc share) and `/api/s/[token]/[slug]/suggest` (directory-child) `{content, note?}`. They resolve the share (reusing the space-scoped `resolveShare` / `resolveShareDoc`), then fail to a **uniform 404** unless the share is live AND `allow_edits` is on AND the doc is `md` (html has no editor) AND — for a directory child — the slug passes the prefix + space guards. Abuse controls: `shareSuggestLimiter` (5/hour per share id), a pre-parse content-length guard, and the `MAX_CONTENT_CHARS` cap.
- **Authorization WITHOUT a Principal.** The public route has no Principal — the SHARE is the authorization, exactly as the public comment route calls `addComment` without one. A new service function `createShareRevision` (in `revisions.ts`) inserts the revision directly from the already-resolved doc/version/share, with `authorName` = the bare share label, `authorKind` = `proposer_label` = `"link:<label>"` — **all forced server-side, never client-supplied**. The staff `createRevision` (and its `isStaff` gate on the staff endpoints) is untouched, so no staff surface is weakened.
- **Owner review + accept.** The existing revisions queue/diff UI now shows a "via share `<label>`" badge (from `proposer_label`, `link:` stripped). Accept flows through Slice-2's `webAuthorCommit`; the commit author is the **proposer** for a share suggestion (the reviewer for a staff one) — it never changes the doc's path/slug. Reject is unchanged. `list_open_revisions` carries `shareId` + `proposerLabel`.
- **The toggle.** `PATCH /api/shares/[id]` now accepts `{ allowComments?, allowEdits? }` (REST-only, admin, no MCP tool) via a new `setShareEdits`. The two flags are INDEPENDENT. Share-page UI: a `SuggestEdit` island (md docs only, edits-on) mirroring `ShareComments`, on both the doc-share and directory-child reader pages.

**Tests.** New `src/app/api/s/[token]/suggest/route.test.ts` (16) + `.../[slug]/suggest/route.test.ts` (8) prove the full uniform-404 matrix (edits-off / unknown / revoked / expired / deleted / html / slug-outside-prefix / slug-in-another-space), the FORCED proposer_label (uncheatable by the client body), independence of the comments/edits toggles, and the per-share 5/hour limiter. New `src/lib/slice3-suggest-edit.test.ts` (git-gated) proves an accepted suggestion is a real commit in a fresh `git clone` authored by the proposer + the projection updates, a rejected one changes nothing, and a visitor reaches no staff surface. `revisions-view-model.test.ts` gains `shareBadgeLabel` cases; `shares/[id]/route.test.ts` gains the `allowEdits` toggle + independence cases. Identity is forced; a visitor's only power is to queue an OPEN revision an owner must accept. Read/write boundaries are unchanged (the accept still runs the Slice-2 owner-role commit).

### Slice 4a — Materialization backfill for legacy DB-only docs (landed)

**What shipped.** The one-time boot backfill that finishes Slice 2's convergence for pre-existing data: every legacy DB-only doc (created by the retired DB-direct `publishDoc`, which wrote Postgres rows but never committed a file) now has its current content committed into its space repo on `main`, so **git is complete** — a fresh `git clone` includes it and the Slice-4 GitHub mirror won't silently omit it. Promoted out of the "Explicitly deferred / Added during the build" list; the owner-decision gate is resolved (built before Slice 4, as prep).

- **`materializeDbOnlyDocs()`** (`src/lib/materialize.ts`) — wired into `instrumentation.register` behind the same best-effort/idempotent precedent as `backfillShareSpaceIds` / `backfillPolicyHooks` (a failure logs, never crashes boot). It enumerates **live** docs only (`unpublishedAt IS NULL AND deletedAt IS NULL`), groups them by space, and per space reads the `main` tree **once** (`listTree` at the tip) into a path Set.
- **Detection rule (one-way).** A doc is "DB-only" iff **no blob exists at its `sourcePath`** on `main`. Only the MISSING case is filled — if a blob exists, git is the source of truth and the projection is **never** written back over it. Every DB-only doc in a space is committed in **one** commit (author = synthetic `Desk (materialization)`, committer = Desk, role forced to `owner` → `main` regardless of `push_policy`) via the Slice-2 `webAuthorCommit` (which creates the bare repo if absent and reindexes so the projection stays consistent — a no-op for the version row, the content hash dedups against the existing current version).
- **Cheap on a clean instance.** On a fully-materialized instance the per-space tree read finds nothing missing → the write set is empty → **zero commits, zero per-doc git spawns** (Set lookups only). A second run makes no new commit (main tip unchanged).
- **Edge cases (handled + logged).** (a) a space whose bare repo doesn't exist yet → `webAuthorCommit`'s `initBareRepo` creates it; (b) the `workspace` default space (where legacy `publishDoc` docs landed) is treated as just another space; (c) the Slice-2 `(space, sourcePath)` collision (two live docs sharing a sourcePath) → commit the first (lowest id), log + skip the rest, never throw; (d) an unsafe `sourcePath` or a doc with no current version → skipped + counted, never blocking the rest of the space.

**Tests.** New `src/lib/slice4a-materialize.test.ts` (6, git-gated) proves: a DB-only doc's content lands at `main:<sourcePath>` in a fresh `git clone` and the doc still projects (slug + content preserved); idempotency (second run → zero new commits, main tip unchanged); unpublished + tombstoned docs are skipped; a doc that already has a matching blob at main is left untouched (no needless commit); the `workspace` space is materialized uniformly; the collision case commits one, counts the collision, and does not throw. No schema migration — the tree-diff detection needs no marker column.

### Slice 4b — Source modes + GitHub mirror-out: backend + mechanism (landed)

**What shipped.** The durability layer (finding 5): per-space **source modes** + a one-way, conflict-free-by-construction **GitHub mirror-out**, so a `hosted` space's canon is backed up to a paired GitHub repo after every main-advancing write, and a `mirrored` space instead treats GitHub as canon (Desk refuses its own content writes). BACKEND + MECHANISM ONLY — the settings UI, its routes, and `docs/remotes.md` are the **4c** follow-up (the service functions the UI will call are built + tested here). DATA-EGRESS + WRITE-BOUNDARY sensitive → fail-closed, exhaustive tests.

- **Schema (`0021_source_modes_mirror`, hand-authored).** `spaces.source_mode` enum(`hosted`,`mirrored`) **NOT NULL DEFAULT `hosted`** (every existing space keeps today's behaviour); `spaces.mirror_remote_url text NULL`; `spaces.mirror_state jsonb NULL` (`{lastMirroredSha, lastAttemptAt, lastError}`); `spaces.mirror_deploy_key_enc text NULL` (per-space SSH private-key override, encrypted). New single-row-ish **`instance_settings`** table (`key text PK`, `value_enc text`, `updated_at`) — no prior settings table existed — holding the instance GitHub PAT under a fixed key. `+ _journal.json` entry (drizzle-kit generate is broken — project convention).
- **Encryption (REUSED, not rolled).** The PAT + the per-space deploy key are stored via the existing `DESK_TOKEN_KEY` AES-256-GCM helper (`src/lib/crypto.ts` `encryptToken`/`decryptToken` — the same machinery that powers share-token reveal). **Write-only**: `src/lib/instance-settings.ts` exposes set/replace(`onConflictDoUpdate`)/clear/**has** (boolean, no reveal); the only decrypt-to-plaintext getter is consumed EXCLUSIVELY by the mirror push, never by any route. Without `DESK_TOKEN_KEY`, `set*` **refuses** rather than storing plaintext. Deploy-key set/clear/has live on the space row (`src/lib/mirror.ts`).
- **Mirror mechanism (`src/lib/mirror.ts`).** `mirrorPush(space)` runs `git push <url> main:main`, **injecting the credential per-invocation and never persisting it**: the URL is passed as an ARGUMENT (never `git remote add`/`git config`, so `.git/config` stays clean); a PAT (https) is supplied via a generic `GIT_ASKPASS` helper that reads the token from the child's ENV (`DESK_MIRROR_TOKEN`) — the script holds no secret and the URL carries only the non-secret `x-access-token@` username (token never in argv/config/disk); a deploy key (ssh) is written to a `chmod 600` temp file referenced by `GIT_SSH_COMMAND` and **deleted in a `finally`**; a `file://`/local remote (the test fixture) needs none. Deploy key preferred over the instance PAT. Every attempt records `mirror_state` and NEVER throws. `mirrorNow(spaceSlug)` is the "Mirror now" service (unknown / not-hosted / no-remote gates).
- **Enqueue + retry (`enqueueMirror(spaceId)`).** In-process module-level queue, **per-space dedupe** (a concurrent enqueue coalesces into one follow-up run so the latest `main` mirrors), exponential backoff, capped retries. Fire-and-forget + crash-proof — it MUST NOT throw into or block the triggering write (same log-and-continue posture as the post-push reindex). Acts ONLY when `source_mode='hosted'` AND `mirror_remote_url` is set, so it is safe to call unconditionally from every hook.
- **Three hook points (Slice 2 converged writes → three, not four).** (a) the git transport route (`src/app/api/git/[...path]/route.ts`) right AFTER the successful post-receive reindex of a `main`-advancing push; (b) `webAuthorCommit` (`src/lib/web-author.ts`) on a successful `target === "main"` commit — this covers web-author UI, `publish_doc`, `POST /api/docs`, `POST /api/docs/[slug]/publish`, `acceptRevision`, AND the 4a materialization; (c) proposal accept (`acceptProposalForSpace`). A proposal write (main untouched) is not mirrored.
- **Mirrored-mode write refusal (the subtle boundary).** A `mirrored` space refuses Desk-originated writes at ONE choke point — `webAuthorCommit` returns `reason: "mirrored"` (→ `publish_doc`/`POST /api/docs`/`/publish`/`acceptRevision` all refuse with a clear error) — plus `acceptProposalForSpace` refuses up front. The **git transport is NOT refused** (it is exactly how GitHub's canon arrives; it never passes through `webAuthorCommit`), and enqueueMirror no-ops on a mirrored space so a received push is never bounced back out (no loop). Reasons threaded to every caller (MCP `publish_doc`/`decide_revision`/proposal-accept; REST `POST /api/docs`, `/publish`, revisions-accept 409, proposals-accept 409).

**Tests.** New `src/lib/slice4b-mirror.test.ts` (19; git-gated where it commits) + `src/app/api/git/[...path]/mirror-transport-e2e.test.ts` (2, live route + git client). Cover: `source_mode` defaults `hosted` (mirror columns null); the fake "GitHub" is a **local bare repo** (`file://`-style path, no PAT/network); after webAuthorCommit / proposal-accept / **git-transport push**, the fake remote's `main` receives the commit and `mirror_state.lastMirroredSha` tracks the tip; a bad-URL mirror push records `lastError` and does NOT fail the write; the PAT + deploy key are stored ENCRYPTED (ciphertext ≠ plaintext, decrypts back) and no service returns plaintext; the mirror never writes the remote/credential into `.git/config`; the deploy-key temp keyfile is cleaned up (no `/tmp` leak); the URL never embeds the token (`x-access-token` only); the mirrored-mode refusal matrix — webAuthorCommit / publish_doc / acceptRevision / proposal-accept all REFUSE, while a git-transport push to a mirrored `main` still SUCCEEDS and projects but does NOT mirror out. Full suite (1602) + `pnpm build` + `pnpm typecheck` green.

**Owner decision (interpretation, flag for review).** "Prefer the deploy key when present, else the PAT" is realized **scheme-aware**: ssh remotes authenticate with the per-space deploy key, https remotes with the instance PAT, and `file://`/local remotes with no credential (this is what lets the test fixture — and any local mirror — push). A remote/credential mismatch (e.g. an https URL with only a deploy key set) records a `lastError` rather than silently succeeding.

**Deferred to 4c (NOT built here).** The space-settings UI (mode / mirror URL / deploy-key generate-rotate + public-key display) and instance-settings UI (PAT set/replace/clear), their owner/admin-gated routes, the "Mirror now" button wiring, and the full `docs/remotes.md` (one-push-target invariant, both mode recipes, the GitHub Action snippet, "protect `main` on the mirror"). GitHub App auth + multiple mirror remotes per space remain deferred per the spec. A materialization commit into a space that has since been flipped to `mirrored` is refused by the `webAuthorCommit` gate (best-effort, logged) — acceptable since mirrored spaces get their canon from GitHub.

### Slice 5 — Agent loop enablement: runbook + `wait_seconds` long-poll (landed)

**What shipped.** The agent-loop enablement layer: the end-to-end runbook for the proof case, plus the optional `wait_seconds` long-poll on `list_events` (5b) — built, because tight-polling latency is real and the park is resource-safe in this Node runtime. No boundary change (the event feed's staff/space scoping is untouched); the risk was purely resource-safety, addressed below.

- **`docs/agent-runbook.md` (new, Part A).** The `acme-growth` proof case, end to end: (1) provision — the bot user, its `writer` membership (`set_space_member` / Members UI), its **principal token** (`/settings/tokens` / `create_token`) for git, and the CF Access **service token** (prod) / `x-dev-role` (dev) for MCP, with the **two-credential reality** called out up front (git token ≠ MCP identity; both resolve to the one bot user so a single `writer` role governs both doors); (2) the cron container loop — clone/pull **`main` only** (with the `master` footgun cross-referenced to `docs/remotes.md`), **read catalogs as files** (frontmatter + `.desk.collection.yml` from the clone — "cloning IS the catalog API", no catalog surface by design), call Amplitude, write `reports/<date>-<topic>.md`, commit, push `HEAD:main`; (3) the review gate — `push_policy=proposal` so reports arrive as proposals (`list_proposals`/`decide_proposal`) or `direct` to auto-publish, with accept → commit → projection → GitHub mirror-out; (4) distribute — a space-scoped directory share on `reports/` + the Slice-3 `allow_edits` suggest path; (5) dispatch — `assign_card` to the bot, the agent polls `list_events(kinds:["card.assigned"], since:<cursor>)` (tight-poll OR the new `wait_seconds`), works it, `move_card` when done, persisting the cursor; (6) the Tier-1→Tier-2 `create_invite` upgrade. Closes with what's NOT built (in-Desk runner, push/webhook dispatch, packs, catalog authoring API).
- **`wait_seconds` long-poll (Part B, `src/lib/events.ts`).** New `listEventsWaiting(opts, waitSeconds, signal?)` wrapping `listEvents`: `waitSeconds<=0` (default) is the exact immediate query; `>0` with events already matching returns NOW; `>0` with nothing pending PARKS, re-querying every `WAIT_POLL_MS` (1 s) until an event matches or the clamped deadline elapses. **Resource safety — the whole risk:** each poll is a fresh short `listEvents` call and between polls the loop only `abortableSleep`s, so **no DB connection or transaction is held across the wait** (a parked request holds an HTTP slot for ≤55 s, never a pool connection — a wall of parked agents can't exhaust the pool). `clampWaitSeconds` bounds the wait to `[0, 55]` (negative/non-finite → 0, over-cap → 55, floored). Client disconnect is wired via `AbortSignal`: `abortableSleep` resolves immediately on abort and the loop breaks, so a hung/abandoned request ends promptly instead of lingering for the timeout.
- **Wiring.** REST `GET /api/events` gains `wait_seconds` (non-integer → 400; range clamped in the service) and passes `req.signal` for disconnect. MCP `list_events` gains a `wait_seconds` arg (clamped in the handler) and threads the request's abort signal: `ToolDef.handler` grew an optional third `ctx?: { signal? }` param (every other handler ignores it), and `server.ts` passes the SDK callback's `extra.signal` into it. Same `{ events, nextCursor }` payload shape on every path.

**Tests.** `src/lib/events.test.ts` +7 (`clampWaitSeconds` bounds; immediate-return-when-pending; `wait<=0` no-park; short-wait timeout returns empty after ~1 s; event-inserted-mid-wait returns promptly with it; abort-signal returns promptly + empty; already-aborted returns immediately). `src/app/api/events/route.test.ts` +4 (immediate when pending; parks then empty after timeout with unchanged `nextCursor`; out-of-range clamped not rejected + non-integer→400; client-abort ends the parked request promptly). `src/lib/mcp/tools.test.ts` +5 (immediate with pending; parks then empty after a short wait; over-cap clamped; omitted = immediate default; non-staff still refused). All waits in tests are 1–2 s to keep the suite fast. Full `npx vitest run` + `pnpm build` + `pnpm typecheck` green.

**Owner decision (flag for review).** `wait_seconds` was **built, not deferred** — the escape hatch (ship tight-poll docs only if a clean park couldn't be done) was not needed: App Router route handlers get `req.signal` (aborts on client disconnect) and the self-hosted Node runtime imposes no hard route-handler timeout, so a ≤55 s park releasing the DB connection between polls is clean. The runbook documents **both** dispatch mechanisms (tight-poll 30–60 s AND `wait_seconds`) so an operator can choose.
